# First Proof: Success Criteria

The first proof is a narrow hybrid-production pilot with one brand, one recurring marketing job, and one closely related constrained control job.

## Policy control test

Run the same brand brain, the same approved assets, and closely related requests under two production modes. The policy system succeeds when changing only the mode produces predictable, explainable differences in creative latitude, tools, and evaluation priorities while leaving canon untouched.

The hybrid job should generate a new context while composing locked canonical elements deterministically. The constrained control should reduce invention, narrow acceptable variation, and rank fidelity above novelty. Both jobs must retain the policy snapshot, entity versions, decisions, and evaluations that explain their outputs.

## Passing conditions

- A reviewer can identify what was locked, flexible, required, conditional, and prohibited before execution.
- Locked assets are reproduced or placed exactly when direct composition is possible.
- The mode change alters system behavior without duplicating or rewriting the brand brain.
- Drift and unrequested changes are detected and surfaced before final approval.
- Every output can be traced to its request, inputs, entity versions, policy snapshot, tools, and evaluation.
- Corrections may create candidate rules but never silently change canon.
- A brand owner can approve a useful output without accidentally making it canonical.
- Registering an ordinary asset batch is fast enough that required metadata is completed honestly, with exceptions receiving focused review.

## Measures

The pilot should record setup time, production time, correction count, unrequested-change rate, locked-element fidelity, approval rounds, cost, and reviewer confidence in the audit trail. The first target is not a universal benchmark; it is a repeatable baseline that makes later improvements and regressions visible.

## Failure conditions

The proof fails if mode selection changes only prompt wording, if locked elements are regenerated unnecessarily, if reviewers cannot explain why an output passed, or if production feedback modifies canon without an explicit governed revision event.
